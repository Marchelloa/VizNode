# VizNode — срез архитектуры

Актуализировано: 16 сентября 2026 года по текущему коду.

## Общий цикл

```text
Console adapter ───────────────────┐
                                  ├→ application.dispatch(event)
DOM → browser-demo → HTTP bridge ──┘             ↓
                                        handlers / input update
                                                ↓
                                              state
                                                ↓
                                         requestRender()
                                                ↓
                                         buildTree(state)
                                           ↙          ↘
                                      Console       SSE → DOM
```

Поддерживаемый сценарий: одно приложение, одно общее состояние интерфейса, Console и одна браузерная вкладка. Несколько вкладок не являются требованием. Мост технически хранит Set соединений и пока не запрещает второе подключение.

## Границы ответственности

- `application.js` не импортирует renderer, readline или DOM API. Он получает callback requestRender, но пока содержит банковскую логику и создаёт demo-сервер.
- `app.js` собирает приложение, Console-адаптер и HTTP/SSE-мост. Общий loop строит дерево один раз для обоих представлений.
- Renderer отображает дерево. Console-адаптер и browser-demo преобразуют действия в события; бизнес-обработчики через renderer не вызываются.
- Браузер получает дерево, не импортирует state и не строит отдельное приложение. pendingInputs — временный локальный ввод до подтверждения.
- `server.js` хранит баланс эмулируемого backend. Баланс в state — отображаемая копия ответа сервера.

## Контракты, существующие в коде

```js
createApplication({ requestRender });
// Возвращает { state, actionHandlers, dispatch }.

// События:
{ type: "action", intent: "open_transfer" }
{ type: "input", bind: "transferForm.amount", value: "500" }
```

Дерево — массив декларативных нод text, action, input, menu и container. Потомки находятся в props.items у menu и props.children у container. Дерево не содержит исполняемых обработчиков; action ссылается на intent, input — на bind.

Строгой рекурсивной схемы и проверки разрешённых intent/bind пока нет. setByPath проверяет существование пути, что не равно разрешению редактировать это поле.

## Выполнение и отображение

Обработчики вручную изменяют state, уведомляют observer и вызывают requestRender. Эти операции пока не объединены общей функцией обновления.

dispatch ожидает результат handler, но submit_transfer не возвращает Promise своего flow: он запускает его через void. Поэтому true означает принятие действия, а не успешный перевод. Защита от повторного запуска перевода в ядре отсутствует.

Console использует один постоянный обработчик line. Проблема вложенных rl.question устранена. При sending новый prompt не выводится, но само по себе это не блокирует входящие события.

Браузерная очередь сохраняет порядок input/action в одной вкладке. HTTP-ответ и SSE-значение совместно подтверждают ввод; идентификатора конкретного события нет. Ошибка ввода не блокирует следующий action, а pending-запись может сохраниться после ошибки или исчезновения поля.

## Степень готовности

Полный основной цикл реализован и признан пользователем соответствующим замыслу прототипа. Автоматического набора тестов нет; устойчивость при задержках, ошибках и повторных действиях требует отдельной проверки. Несколько вкладок и конфликты между ними исключены из текущего объёма.

## Направление развития

Цель — понятный автору приложения способ задать состояние, дерево и обработчики. Минимальный runtime-контекст, единое обновление состояния и передача прикладных зависимостей остаются предметом проектирования, а не существующим API.

Предлагается сначала определить поведение текущего цикла при ошибках и async-действиях, затем проверить проектируемый API на втором небольшом приложении. После уточнения общих контрактов — строгая валидация дерева и заменяемый InterfaceBuilder; AI provider остаётся последующим необязательным расширением.
